# disagreement-conversation — 理性表达分歧与对齐技能

## R — 原文 (Reading)

> 表达分歧时，重点是要表明“我与最终目标是绝对一致的（Show alignment in the goal）”，只是思考角度或路径不同。阐明风险和影响，并提供替代解决方案（Alternative solution）。
> 例如：“我完全理解并支持我们 [达成目标] 的决心。但我担心这会导致销售额短期下滑，以及员工满意度下降。我们对此能接受吗？为了降低这个风险，我们是否能采用 [替代方案]？”
> 一旦上级在知晓风险后仍做出决定，应顺从并配合执行。你要分清什么是一个“你”的问题，什么是一个“他们/公司”的问题。
>
> — 麦克老李, 如何應對和老闆的意見分歧

---

## I — 方法论骨架 (Interpretation)

与高级领导发生分歧时，许多职场人常犯两个错误：要么激烈辩论（显得刺头、缺乏大局观），要么唯唯诺诺（导致线上出问题后自己背锅）。
本技能提供了一种**“理性分歧架构”**：
1. **统一战线**：首先明确表态“我和你在战略终点上完全一致”，消除领导的防御心。
2. **客观解构风险**：不用情绪化字眼（如“这很蠢”），而是站在高管维度说明“如果这么做，会对时间、金钱或客户带来什么具体的负面影响（Concerns）”。
3. **奉上备胎**：必须同时提供替代方案（Alternative solution）。
4. **Dis-commit**：明确决策权在对方，一旦对方在明知风险下拍板，作为下属要全力以赴去执行（They problem），不带情绪。

## A1 — 书中的应用 (Past Application)

### 案例 1: 麦克老李的方案推敲
- **问题**: 麦克老李在亚马逊工作时，老板强推一项可能会导致团队超载、研发质量大幅下滑的工期压缩计划。
- **方法论的使用**: 老李没有抱怨“我们干不完”，而是找到老板沟通：“我完全同意我们需要在 Q3 抢先占领这个市场。不过如果按照现有的快速发布计划，我的 concern 是我们的报错率可能会突破 5%，进而影响客户满意度分值，而且这会迫使我暂停您上周安排的另一项核心业务。您看对于这个代价，我们是可以接受的吗？或者，我们是否可以把第一期范围缩减一半，用方案 B 逐步灰度发布？”
- **结论**: 将争论转换为“风险与替代方案的抉择”。
- **结果**: 老板意识到压缩工期会导致其他核心业务停滞，最终接受了老李的方案 B。

## A2 — 触发场景 (Future Trigger)

### 用户会在什么情境下需要这个 skill?

1. 老板在会议上提出了一个明显存在技术漏洞、或可能对用户体验造成伤害的需求，需要用户去沟通纠偏。
2. 老板安排的紧急插队任务，会导致用户手头正在进行的重要项目延误，需要跟老板对齐优先级。
3. 方案评审中，用户认为老板的决策存在严重的宏观盲点，想进行委婉的越级或横向警示。

### 语言信号 (用户的话里出现这些就应激活)

- "老板提的需求很不合理，我该怎么拒绝"
- "怎么和老板说我的方案更好"
- "老板不懂技术非要瞎指挥，怎么撕"
- "how to push back on my manager's request"
- "negotiate priorities with leadership"

### 与相邻 skill 的区分

- 与 `guided-reporting` 的区别: `guided-reporting` 用于**汇报常规进度或主动发起提案并锁定结果**；而本技能用于**被动收到指令、产生意见分歧时的防御性说服**。

## E — 可执行步骤 (Execution)

当 skill 被激活后，agent 应按以下步骤执行:

1. **确立共同目标 (Build Goal Alignment)**
   - 提取对方提案的战略终点（例如“提升转化率”/“快速响应市场”）。
   - 完成标准: 撰写第一句首肯话术，例如：*“I'm fully aligned with the goal of [目标]...”*。
2. **翻译商业 Concern (De-personalize Risk)**
   - 将用户的技术异议翻译为四维商业指标风险（时间、金钱、客户满意度、未来机会），坚决不能使用情绪化否定。
   - 完成标准: 撰写风险阐述句：*“My primary concerns with the current path are: (1)... (2)...”*。
3. **配置替代选择 (Configure Alternatives)**
   - 引导或帮助用户写出至少一个可行的替代方案（Alternative solution）。
   - 完成标准: 形成完整的沟通脚本，包含替代方案陈述和确认性发问（“Are you comfortable accepting this risk, or should we consider [Alternative]?”）。
4. **决策分界确认**
   - 提醒用户：若老板回复“是的，我知道这个风险，但我依然坚持这样做”，立刻使用回复模板：*“Understood. I will fully align and execute this plan with the team.”*（执行完毕后不再纠结）。

## B — 边界 (Boundary)

### 不要在以下情况使用此 skill

- 当发现老板的决策存在重大财务作假、违法经营或危害员工人身安全的违规红线时。这类场景不能“disagree and commit”，必须立刻根据公司合规途径（Compliance/HR）上报。

### 作者在书中警告的失败模式

- **自闭型执行**：嘴上说“Ok”，回去以后在团队里抱怨“这都是老板瞎指挥”，消极怠工。这会彻底毁掉个人的职业口碑。
